Overseer: tamper with a record, watch verification fail

Six memory events written by AI agents. Each row stores when the fact was true (valid time) and when the agent recorded it (transaction time), plus a SHA-256 hash that covers the previous row's hash. Click any text in the "fact" column, change it, then press Verify.

Red rows fail verification. Amber rows carry a recomputed hash that no longer matches what the next row expected, which is the point: fixing one hash is not enough, you would have to rewrite every later row too, and the published anchor at the end would still disagree.

What this demonstrates

Hash chaining. row.hash = SHA-256(prev_hash + canonical JSON of the row). Any change to any earlier row changes every later hash.
Bitemporal fields. "valid from" is when the fact held in the world; "recorded at" is when the agent wrote it. Corrections are new rows, never edits, so you can ask "what did the agent believe at 10:05?"
Append-only memory. There is no edit operation in the real system. This page lets you edit only to show what verification catches.
Anchoring. In the paper, the final hash is anchored externally (for example a timestamp proof), so even rewriting the whole ledger is detectable.
From Overseer: Tamper-Evident Memory for AI Agents Using Bitemporal Knowledge Graphs by Akhil Reddy Gaddam · Zenodo DOI 10.5281/zenodo.23023088. The demo runs entirely in your browser with the Web Crypto API; nothing is sent anywhere.
